# Sprint Plan — Food Decision Sprint

**Team:** 2 Product Designers  
**Duration:** 2 Weeks  
**Goal:** Build and validate a no-code prototype that tests PMF for a low-effort, delightful food decision app  
**Reference:** See [PROJECT-OVERVIEW.md](./PROJECT-OVERVIEW.md) for full context

---

## Sprint Structure

```
Week 1 — Understand & Define     →   Research, synthesis, problem framing
Week 2 — Design & Validate       →   Prototype, test, PMF signal
```

---

## Week 1 — Understand & Define

### Day 1 — Align & Recruit

**Goal:** Get the team fully aligned on the sprint and start recruiting research participants.

- [ ] Read and review PROJECT-OVERVIEW.md together as a team
- [ ] Agree on the north star: "fun and delightful, not a chore"
- [ ] Agree on what "minimum daily input" means concretely (e.g. ≤1 tap per day?)
- [ ] Review and finalise RESEARCH-GUIDE.md interview questions
- [ ] Recruit 5–8 participants matching the primary user persona (urban corporate professional, metro city, has a cook or cooks at home)
- [ ] Set up a shared working space (FigJam or Miro) for synthesis

**Output:** Team aligned, participants recruited, interview guide ready

---

### Day 2 — User Interviews (Round 1)

**Goal:** Validate the problem and understand current behaviour in depth.

- [ ] Conduct 3 interviews using RESEARCH-GUIDE.md
- [ ] Record key quotes and observations in the shared board
- [ ] Note any surprising or contradictory signals immediately after each session

**Output:** 3 interviews completed, raw notes captured

---

### Day 3 — User Interviews (Round 2) + Early Synthesis

**Goal:** Complete interviews and begin spotting patterns.

- [ ] Conduct 2–3 more interviews
- [ ] Begin affinity clustering on the shared board — group observations by theme
- [ ] Identify the top 3 pain points with strongest signal

**Output:** All interviews complete, early themes visible

---

### Day 4 — Synthesis & Problem Reframe

**Goal:** Distil research into a sharp, evidence-backed problem statement and user needs.

- [ ] Complete affinity clustering
- [ ] Write a refined problem statement grounded in research (revise PROJECT-OVERVIEW.md if needed)
- [ ] Map the current state user journey: from waking up → deciding what to eat → eating
- [ ] Identify the 2–3 highest-friction moments in the journey
- [ ] Define the "How Might We" questions that will guide ideation

**Output:** Refined problem statement · Current state journey map · HMW questions

---

### Day 5 — Ideation & Concept Direction

**Goal:** Generate a wide range of ideas and converge on a prototype direction.

- [ ] Run a 20-minute solo sketching session — each designer sketches 6–8 concepts
- [ ] Share and discuss concepts — look for complementary ideas
- [ ] Vote on the most promising direction using dot voting
- [ ] Agree on a single concept to prototype
- [ ] Define the key screens/flows needed for the prototype
- [ ] Write a one-paragraph "prototype hypothesis": what you're testing and what success looks like

**Output:** Chosen concept · Key screens defined · Prototype hypothesis written

---

## Week 2 — Design & Validate

### Day 6 — Prototype Setup

**Goal:** Build the structural skeleton of the prototype.

- [ ] Set up the prototype file in Figma (or chosen tool)
- [ ] Design the onboarding flow — minimum input to get personalised suggestions
- [ ] Design the core daily suggestion surface — what users see when they open the app
- [ ] Placeholder content is fine at this stage; focus on flow and information architecture

**Output:** Onboarding flow + core suggestion screen in prototype

---

### Day 7 — Prototype Build — Core Flows

**Goal:** Build the flows that test your three key assumptions.

- [ ] Design the meal suggestion detail view (what to cook / ask cook / order)
- [ ] Design the light progress/tracking surface — no calorie counting
- [ ] Design the cook communication flow (how suggestion reaches the cook)
- [ ] Wire up all screens with Figma prototype links

**Output:** Fully linked prototype covering core user journey

---

### Day 8 — Prototype Polish & Test Prep

**Goal:** Make the prototype feel real enough to generate honest reactions.

- [ ] Add visual polish — typography, colour, spacing, delight moments
- [ ] Write realistic content for all screens (real dish names, real suggestions)
- [ ] Write a test script based on RESEARCH-GUIDE.md validation questions
- [ ] Run an internal walkthrough — each designer acts as a participant
- [ ] Fix any broken flows or confusing moments

**Output:** Polished prototype · Test script ready

---

### Day 9 — Usability & PMF Testing (Round 1)

**Goal:** Get real reactions from target users and collect PMF signals.

- [ ] Conduct 3 test sessions using the test script
- [ ] Ask the Sean Ellis PMF question: "How would you feel if you could no longer use this product?"
- [ ] Ask direct willingness-to-pay questions (see RESEARCH-GUIDE.md)
- [ ] Capture observations immediately after each session

**Output:** 3 test sessions complete · PMF signals captured

---

### Day 10 — Testing (Round 2) + Sprint Readout

**Goal:** Complete validation, interpret findings, and decide next steps.

- [ ] Conduct 2 more test sessions
- [ ] Tally PMF signal: what % of participants said "very disappointed"? (Target: >40%)
- [ ] Identify the top 3 things that worked and top 3 things to fix
- [ ] Write a one-page sprint readout:
  - Were the 3 assumptions validated, invalidated, or inconclusive?
  - What is the recommended next step?
  - What would you build first if you had an engineer?
- [ ] Update PROJECT-OVERVIEW.md with findings

**Output:** Sprint readout complete · PMF signal interpreted · Next steps defined

---

## Definition of Done

The sprint is complete when:

- [ ] 5+ target users have used the prototype
- [ ] All 3 key assumptions have a clear validated / invalidated / needs more research status
- [ ] A shareable prototype exists
- [ ] A sprint readout document exists with a clear recommendation
